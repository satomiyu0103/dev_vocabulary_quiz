## 1. 背景と目的

### 1.1 背景

RPA_scripts・Data_Science の実装では、英単語・API 名・命名規則の理解がボトルネックになる。汎用の英単語アプリでは「自分のコード文脈」に即した復習が難しい。

2026 年に **開発語彙単語帳（dev-vocabulary）** を schema v2 で整備し、265 枚の JSON カードを `doc/life/career/dev-vocabulary/` に集約した。復習手段として当初は Gemini Gem（チャット採点）を試したが、採点の不安定さ・状態リセットにより学習 UX に耐えないと判断し、**ブラウザ上の JavaScript 採点**に切り替えた。

### 1.2 目的


| 目的          | 説明                                         |
| ----------- | ------------------------------------------ |
| **定着**      | 日常の意味とプログラミング上の意味をセットで覚え、コードを読む・書く速度を上げる   |
| **採点の確実性**  | LLM に依存せず、同じ選択で常に同じ正誤結果を返す                 |
| **手軽なアクセス** | 静的サイトとして Cloudflare Pages に公開し、URL から毎日開ける |
| **正本の分離**   | カード編集は Documents 秘書層、公開 UI は本プロジェクトに分離     |




### 1.3 対象ユーザー

- 本人（RPA / DS 開発の学習者）
- 就活・ポートフォリオ文脈で「実プロジェクト由来の語彙学習」を説明する際の参照先



### 1.4 スコープ


| 含む                        | 含まない           |
| ------------------------- | -------------- |
| `public/` のクイズ UI・統合 JSON | サーバ API・ユーザー認証 |
| Cloudflare Pages デプロイ     | カード編集 UI       |
| ローカルプレビュー・同期手順            | Gem 採点（一時停止）   |




### 1.5 学習運用（語彙正本側）

- 新規カード追加: **1 日 5〜15 枚**
- 復習ツール正本: ブラウザ 4 択（本プロジェクト）
- Gem: 一時停止（Gemini 安定後に再試行）

## 3. 設計



### 3.1 データ設計（schema v2）

**正本スキーマ**: `doc/life/career/dev-vocabulary/schema.json`


| 区分      | フィールド                                                           | 用途                              |
| ------- | --------------------------------------------------------------- | ------------------------------- |
| 識別      | `id`, `type`, `tier`, `term`                                    | 一意 ID・種別・優先度・出題語                |
| 意味      | `meaning_general_ja`, `meaning_programming_ja`, `usage_note_ja` | 問題文・解説                          |
| 例       | `examples_general[]`, `examples_code[]`                         | 解説（各最大 3 件）                     |
| 混同      | `confusable_with[]`                                             | 誤答候補の優先源                        |
| 禁止語     | `bad_example`, `good_alternative`                               | `anti_pattern` 用                |
| 品質      | `enrichment_status`                                             | `full` / `partial` / `scaffold` |
| 復習（未使用） | `srs_level`, `last_reviewed`                                    | 将来の SRS 用                       |


**カード種別（**`type`**）**: `identifier` / `pattern` / `anti_pattern` / `stdlib` / `package` / `method`

**デッキ構成（265 枚・すべて** `full`**）**


| デッキ                              | 枚数  |
| -------------------------------- | --- |
| P0 横断（`p0_cross_project.json`）   | 97  |
| P1 スタック別（`p1_stacks/*.json`）     | 70  |
| P2 プロジェクト別（`p2_projects/*.json`） | 98  |




#### 3.1.1 統合 JSON の既知問題

現行 `export/all_cards_v2.json` および `public/all_cards_v2.json` は:

- 配列 **530 件**、`meta.card_count: 530`
- **ユニーク id は 265 件**（全 id が 2 回ずつ同一順で複製）
- UI の「出題済み X / total」が実枚数の 2 倍になる

**修正方針（開発 backlog）**: 統合ビルドスクリプトで重複除去し、`meta.card_count` と配列長を一致させる。`validate_decks.py` に export 向け id ユニーク検証を追加する。

### 3.2 クイズロジック設計

```text
loadJson()
  → allCards を保持
  → ユーザーが mode を選択
  → filterCards(allCards) でプール生成
  → refreshPool(): usedIds で除外。枯渇時は usedIds をクリア
  → pool からランダムに 1 枚を current に設定
  → pickDistractors(current, candidates)
       1. confusable_with / related_terms から候補
       2. 不足時は同プールからランダム
       3. まだ不足なら "—" でパディング
  → [current.term, ...3 distractors] をシャッフル → 4 択
  → 回答 → showFeedback() → usedIds に current.id を追加
```

**誤答設計の意図**: ランダムより `confusable_with` を優先し、似た語の区別を学習する。

**採点**: クリックした選択肢の index と `correctIndex` を比較。状態はメモリ内のみ（永続化なし）。

## 4. アーキテクチャ



### 4.1 システム構成

```text
┌─────────────────────────────────────────────────────────┐
│ Documents 秘書層 git                                     │
│  doc/life/career/dev-vocabulary/                         │
│    build_decks.py → デッキ JSON                          │
│    validate_decks.py → 検証                               │
│    export/quiz.html + all_cards_v2.json                  │
│    sync_to_web.ps1 ─────────────────────┐                │
└─────────────────────────────────────────│────────────────┘
                                          ▼
┌─────────────────────────────────────────────────────────┐
│ dev_vocabulary_quiz（独立 git）                          │
│  public/index.html + all_cards_v2.json                   │
│    → git push → Cloudflare Pages（出力: public）         │
└─────────────────────────────────────────────────────────┘
                                          ▼
┌─────────────────────────────────────────────────────────┐
│ ブラウザ（クライアントのみ）                              │
│  fetch(JSON) → インライン JS で採点・表示                │
└─────────────────────────────────────────────────────────┘
```



### 4.2 技術スタック


| 層      | 技術                                                    |
| ------ | ----------------------------------------------------- |
| フロント   | HTML5 + CSS + vanilla JavaScript（`index.html` 内インライン） |
| データ    | JSON（schema v2）                                       |
| ホスティング | Cloudflare Pages（ビルドなし）                               |
| ローカル確認 | `python -m http.server`（`public/` 配下）                 |




### 4.3 リポジトリ境界


| リポジトリ                 | 管理対象                          |
| --------------------- | ----------------------------- |
| Documents             | 語彙カード正本・ビルドツール・export         |
| `dev_vocabulary_quiz` | 公開 UI・プロジェクト doc・`.cursor` 運用 |




### 4.4 同期・デプロイ手順

```powershell
# Documents ルートで
python doc/life/career/dev-vocabulary/tools/build_decks.py
python doc/life/career/dev-vocabulary/tools/validate_decks.py
# （統合 JSON 生成 — 整備後はここにスクリプト化）
powershell -NoProfile -ExecutionPolicy Bypass -File doc/life/career/dev-vocabulary/tools/sync_to_web.ps1

# プロジェクト repo で
# commit → push → Cloudflare Pages 自動デプロイ
```

詳細: [CLOUDFLARE_DEPLOY.md](../../CLOUDFLARE_DEPLOY.md)

### 4.5 セキュリティ

- サーバサイド処理なし。認証なし
- `public/` は公開前提。API キー・個人情報を置かない
- 解説表示は現状 `innerHTML`（自前 JSON なら低リスク。改善時は `textContent` / `createElement`）
- コミット前: `python scripts/check_no_sensitive_patterns.py`
